# Petite Lueur PL｜PL3 唯一官方網站安全遷移

更新：2026-11-04。本文是遷移紀錄與驗收門檻；任何勾選項目都必須依實際證據更新，不以程式碼提交或部署成功代替營運驗收。

## 目標及現況

- 唯一對客官方首頁、商店、詢價、查單入口：PL3 Worker 同一個網站來源（origin）。
- 現有 PL3 Worker：\`https://pl3-staging-api.petitelueur-pl.workers.dev/\`。Worker 名稱仍含 \`staging\`，日後有自訂網域或正式 Worker 才能更換美觀的公開網址；未取得網域前不能宣稱有專屬網域。
- 原 GitHub Pages：\`https://a-little-light-for-every-day.github.io/petite-lueur-pl/\`。切換前保持可用；完成後保留舊連結轉址頁，不立即 unpublish，避免既有社群貼文及收藏變死鏈。
- 原 Apps Script 公開申請網址：先從社群、LINE 選單、官網 CTA 移除接單入口；**只在核實無活躍客戶、無必要後端依賴後**考慮下架。現有 PL3 的 Notion／Sheets 同步仍使用 Apps Script webhook，不可依網址外觀一併停用。
- Google Sheets 公開進度與 Google 表單匿名提問目前為獨立公開功能；若未被 PL3 等價功能取代，不可在退役時一併刪除。

## 分階段執行與停止條件

1. **建置與隔離測試**：PL3 自有根頁、隱私頁與入口自動測試；本階段不動原官網、不寄客人通知、不產生正式新訂單。
2. **PL3 站內驗收**：部署後逐一確認 \`/\`、\`/shop\`、\`/services\`、\`/account\`、\`/privacy\`、\`/health\`。測試 OTP／跨頁工作階段、查單、下單、付款回報、重試防重、後台履約與 Notion／Sheets 同步。採用明確標記的測試單，禁止污染真實應收與重複寄信。
3. **公開入口盤點**：Threads、Plurk、FB、LINE 官方帳號、LINE 群組、IG、X、Email 範本、GitHub Pages 表單/CTA、Google OAuth 首頁與隱私連結。更新所有可控的官方入口指向同一 PL3 根網址。
4. **舊 GitHub Pages 軟退役**：先在舊頁顯示清楚的遷移公告與「前往 PL3」入口；觀察舊站已提交／待付款訂單及查單需求；確認後才替換成指向 PL3 的安全轉址頁。保留既有連結的可追溯性。
5. **舊申請端點退役**：透過後台日誌及資料表核對是否仍接新單；先關閉「對客新單寫入」，保留讀取歷史、同步接收、回退能力。Apps Script webhook 與後台工作流未完成替代前，**不得刪除或停用**。
6. **觀察期與結案**：至少 30 日監看訂單完整性、付款回報、同步衝突、OTP 失敗與舊入口流量；備份、維持可回退，才考慮停止舊版程式的其餘公開服務。

## 驗收必須留下的證據

- PL3 根頁及各路由實際 HTTP 狀態、操作錄影／截圖及日期。
- 商店團次／規格／庫存顯示與 Notion／試算表對照，含已結單、流團、隱藏商品。
- OTP 驗證、跨頁、重整、登出、逾時與錯誤帳號測試；敏感工作階段不得出現在網址。
- 測試單訂購、付款回報、通知待審、履約明細、重送去重、同步失敗重試結果；對客通知仍須主購審核。
- 舊站所有可控社群入口更新紀錄及遷移後的連結點擊查驗。
- 舊站與同步 webhook 停用前的依賴盤點、完整備份及可行回退方法。

## 回退

在未完成第二階段驗收前，GitHub Pages 原頁面保持不變。若 PL3 發生無法登入／下單／查單、同步資料不一致，立刻停止新入口宣傳，將已更新的入口指回仍可用的舊站；保存已有 PL3 訂單紀錄，禁止刪除 D1 或直接重新寄出結果不明的郵件。

**限制：** 目前沒有在這次變更中購買網域、刪除資料庫、關閉 GitHub Pages、停用 Apps Script 或批次發送對客通知。
